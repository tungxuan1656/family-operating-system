# 10 Decision Log and ADR

## Goal

Record important cross-team technical decisions and their rationale.

## When To Add An ADR

Create an ADR when a decision:

- affects both frontend and backend,
- changes trust boundaries or contract expectations,
- introduces significant long-term tradeoffs,
- deviates from documented baseline rules.

## ADR Index

| ADR ID  | Date       | Status   | Decision Title   | Owner      | Related PR |
| ------- | ---------- | -------- | ---------------- | ---------- | ---------- |
| ADR-001 | YYYY-MM-DD | proposed | Example decision | Unassigned | -          |

## ADR Template

Copy this section for each decision:

### ADR-XXX: Title

- Date: YYYY-MM-DD
- Status: proposed | accepted | superseded | deprecated
- Owners: Name(s)
- Related docs: links
- Related PRs/issues: links

#### Context

Describe the problem and constraints.

#### Decision

State what is chosen.

#### Consequences

Describe positive outcomes, costs, and risks.

#### Alternatives Considered

List alternatives and why they were not selected.

#### Follow-Up Actions

List concrete action items with owner and due date.
